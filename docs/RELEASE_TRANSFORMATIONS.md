# Release transformations and reproducibility boundary

This release was assembled independently of the working research directory. Only the dependency closure of the current full paper and its numerical evidence was selected. Historical narrative, reviews, planning, obsolete paper versions, cloud provisioning code, private infrastructure records and unused bulk data were excluded.

## What changed for packaging

1. Experiment directories and analytic filenames have descriptive portable names. Absolute local provenance paths were omitted, not published. Original request seeds and statistical seed constants remain unchanged.
2. Raw provider envelopes, request/account identifiers, duplicate nested request objects, latency and serving-account metadata were removed. Scientific response text, parsed answer, success/failure, attempt identity, finish reason, token totals and the actual model request are retained when present in the original records. No missing outcome was repaired or generated during packaging.
3. Analytic import helpers are local and dependency-light. Cloud setup/teardown is not needed for numerical replay. Historical infrastructure cost calculations are retained as aggregate results instead of depending on private lifecycle logs.
4. Manifest checks referencing changed bytes were rebound to the release bytes and explicitly marked `release_integrity_only`. They are integrity checks, not claims that edited programs or sanitized files were frozen before outputs. Original scientific random seeds, comparisons and estimator code are retained. Current results are compared against the pre-packaging numeric targets.
5. The 1 October research draft's PDF and scientific sources are copied without editing scientific content. Official style attribution is preserved. Rebuilding uses fixed timestamps; the committed PDF's hash identifies the distributed version. The conference submission and private research workspace are not modified.
6. Figure-generation code for earlier development displays was extracted from a larger manuscript-writing utility. It reads recorded effect matrices. Earlier plots are regenerated by the earlier replay; all figures required by the current manuscript are distributed as source assets. The latest replay reconstructs numerical analyses, not every current figure's original plotting pipeline. Supporting development effects and criterion decisions remain separately labeled from prospective tests.

The public repository starts with a fresh allowlisted export rather than carrying
superseded manuscript releases or private project history. Existing private
repositories are preserved without history rewriting. Additional packaging code
orchestrates the ten existing capsules and compares their expected outputs; it
does not change their statistical estimators or generate new model responses.

## What the release can establish

- Recorded-choice replay reconstructs core fresh, transport and common-pool results, including bootstrap intervals, from candidate scoring maps and selector responses.
- Development point-estimate replay and the earlier 13-scenario capsule independently reconstruct their stated outcomes; the earlier capsule also reconstructs its focal adjusted intervals. Other historical supplementary summaries are supplied as supporting evidence, not silently claimed as independently adjudicated or freshly repeated experiments.
- Input requests, candidate lists, scoring maps and failures can be inspected. Preserved raw model *text* is distinct from excluded provider/account envelopes.
- Optional request replay is a new inference run. Exact historical hardware/quantization, remote route behavior and clinical label validity are outside the claim of a clean numerical rebuild.

No private planning records or internal reviews are required to run the public-facing package. No credentials were retrieved, requested or stored for packaging; GitHub authentication uses the pre-existing authenticated session.

Original opaque experiment/request IDs, scoring-version names, and hash seed namespaces are retained where they are inputs to reproducibility. They carry no author identity or account access and are not internal review verdicts. Renaming a hash namespace would change randomized ordering and seeds, so these scientific constants are not cosmetically altered. The terminology rule implementations are included under `src/terminology_reference/` for inspection; rebuilding their original source authority additionally requires the named public terminology inputs. They are not a claim that a fresh clinical adjudication is included in the offline replay.
